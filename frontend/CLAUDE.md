# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

This directory is the frontend for a distributed video surveillance system (the broader repo also
contains `server-a`, `server-b`, and `camera-simulator` as sibling directories, orchestrated via the
root `docker-compose.yml`). The frontend is a TanStack Start (React 19 + TanStack Router, file-based
routing) app that authenticates against `server-b` and will render live camera streams.

- `server-b` (default `http://localhost:3001`) owns auth (`/auth/login`) and session-protected routes
  (`/protected/*`) — the frontend's `api-client.ts` talks to it directly with `credentials: 'include'`
  (cookie-based session).
- `server-a` fronts the RTSP/MediaMTX stream management (gRPC to a stream-manager, see
  `server-a/src/grpc/stream-manager.proto`) — not yet wired into the frontend beyond the `/stream` route
  placeholder.

## Commands

Package manager is **pnpm** (see `packageManager` in package.json), even though the README/scripts
mention npm — use pnpm for consistency with the lockfile and workspace.

```bash
pnpm install
pnpm dev            # vite dev server on port 3000
pnpm build          # vite build (production bundle, Nitro server output)
pnpm preview        # preview a production build
pnpm lint           # eslint
pnpm format         # prettier --write . && eslint --fix
pnpm check          # prettier --check .
pnpm generate-routes # tsr generate — regenerate src/routeTree.gen.ts from src/routes/*
```

There is no test suite configured in this package yet.

`src/routeTree.gen.ts` is generated by TanStack Router (`tsr generate` / automatically by the vite
plugin on `pnpm dev`/`pnpm build`) — do not hand-edit it; add/edit files under `src/routes/` instead
and regenerate.

## Environment

`.env` sets `VITE_SERVER_B_URL` (default `http://localhost:3001`), read in `src/lib/api-client.ts`.
When running the full stack via the root `docker-compose.yml`, `server-a` is on `3000` and `server-b`
is exposed on host `3001`.

## Architecture notes

- **Routing**: file-based via TanStack Router, files live in `src/routes/`. `src/routes/__root.tsx` is
  the shell (renders `<html>`, includes TanStack Devtools panel). `src/router.tsx` wires the generated
  `routeTree` into the router instance.
- **Auth flow**: `/` (`src/routes/index.tsx`) is a client-side gate — on mount it calls
  `apiClient.checkAuth()` (hits `server-b` `/protected/`) and redirects to `/stream` or `/auth/login`
  based on the result. There is no route-level `beforeLoad` guard yet; auth checks happen in component
  effects.
- **API access**: all backend calls go through `src/lib/api-client.ts` (a plain object of async
  functions, not a class/hook) — extend this file rather than calling `fetch` directly from components.
- **Forms**: built with `react-hook-form` + `zod` via `@hookform/resolvers/zod`, using the shadcn
  `Form`/`FormField`/`FormItem` primitives in `src/components/ui/form.tsx` (see `login-form.tsx` for the
  pattern to follow for new forms).
- **UI components**: shadcn/ui ("new-york" style, zinc base, no RSC), configured in `components.json`.
  Add new primitives with `pnpm dlx shadcn@latest add <component>` rather than hand-rolling them; they
  land in `src/components/ui/`.
- **Import alias**: `#/*` maps to `./src/*` (defined in `package.json` `imports`, mirrored in
  `components.json` aliases and `tsconfig.json`) — use `#/lib/...`, `#/components/...`, etc., not deep
  relative paths.
- **Styling**: Tailwind CSS v4 via the `@tailwindcss/vite` plugin, entry styles in `src/styles.css`.

## Conventions

- No semicolons, single quotes (Prettier config: `semi: false, singleQuote: true`).
- `import/order`, `sort-imports`, and `@typescript-eslint/array-type` are disabled in
  `eslint.config.js` — don't fight the linter trying to reorder imports or "fix" array type syntax.
- Shadcn component installs must use the **latest** version (per `.cursorrules`).
